# 参考视频动效复刻

把参考作品拆成可测量的时间、形状和对象关系，再用代码重建。交付可编辑工程、实际成片、同时间轴对比和已知差异；不用“画面像”代替“动作关系对”。

## 先锁定任务

从用户材料取得参考文件或原作链接、目标片段、输出要求、指定渲染器和验收重点。信息足够就开始，缺少会改变制作方向的内容才问。以文件探测结果为准，不把画面上的“1080p/60fps”字样当文件参数。记录来源与素材使用边界。

直链文件请求失败不等于作品页无法观看。若仅文件请求 403、没有明确的操作或访问权限拒绝，可尝试作品页正常播放器；遇明确访问限制则停止，不绕过。正常可用渠道仍无法查看时，说明缺口并请求可用文件；只凭文字可以做风格练习，但不得声称已完成参考复刻。公开分享与制作成片是分开的动作。

## 工作方式

1. 分析参考：先全片正常速度观看，再做总览；在复杂转场前后从稳态到稳态加密抽帧。记录看过的区间，区分“提取了所有帧”和“看过所有帧”。无法播放或听音时明确标注。
2. 建事件表：每段记录起止时间、构图、对象身份、静止/加速/减速/过冲/回弹、文字遮罩、相机与音效。帧率不同时按呈现时间 PTS 对齐；可变帧率参考不可直接用帧号除固定帧率。
3. 先做连续骨架：让同一对象在转场中保留位置、体积和身份。相关对象共用状态，例如指针与进度、数据点与曲线、按钮与通知、方柱与粒子。只有真正切镜才切断关系。
4. 再补视觉：按影响大小校正节奏和因果关系，再调轮廓、字号、错峰、颜色、光照与纹理。不要给全部动画套同一缓动，也不要在普通经过点制造假停顿。真实停顿应保留。
5. 小段迭代：每次选一组可观察的问题，记录时间、参考行为、当前偏差、修复和复查结果。静帧看形状，连续播放看运动；粒子和 3D 可以用近似算法，但要说明差异。
6. 验证交付：固定版本后从实际导出文件检查时长、尺寸、帧率、帧数、完整解码、时间戳与音轨。对照首尾、阶段稳态和关键转场，正常速度播放并听音。未做的检查单列，不能用源码测试代替成片测试。

## 实现和对比约束

- 单帧应由时间和稳定输入决定；相同时间重复渲染、乱序 seek 后应一致。需要随机效果时使用固定种子或稳定粒子 ID。
- 用户指定的框架必须真实导出才可署名为该框架产物。若改用 Canvas + FFmpeg 等路线，先满足用户授权，再准确说明。
- 对比保留两边完整画幅并标“原作 / 复刻”；先按相同起点同步播放，不偷偷变速掩盖节奏差异。必要的偏移或重定时需明确标注。
- 统一比较起点时记录 PTS 偏移；帧率转换保持时长并说明重复/丢帧方式，默认不做运动插帧。时长不同时保留全部时段，结束的一侧明确标记，不默认截掉差异。
- 对比音轨说明来自哪一边，避免双轨叠响。未知授权的音乐先静音或换成有许可的音乐，不能把换曲后效果说成原片音画一致。
- 技术通过、视觉接近、主观满意是三个独立结论。无新阻断且达到当前验收目标就交付，不无限微调。

## 交付与复用

提供成片、可编辑工程、比较材料、来源/许可与简短差异清单；明确渲染路线、实际查看范围和未验证项。公开包只带有权分发的资产，不带私有路径、登录信息、工作日志或第三方原片。

完整包中可按需读取：
- `references/reusable-prompts.md`：本次整理的复用提示词，非历史原话。
- `references/case-daryl-r2.md`：本例真实材料、迭代和复现边界。
- `references/credits-and-sharing.md`：本例署名及公开分享检查。
- `scripts/check_video.py`：用 FFmpeg/ffprobe 检查导出事实，不判断审美。
- `references/checking-and-use.md`：使用方式、脚本调用与已完成的验证范围。

单文件使用时，以上资源是可选增强，不影响执行核心流程；也可以直接使用下面这段启动提示词。

## 启动提示词

请按这份 Skill 复刻我提供的参考视频。先分析实际视频的节奏、构图和跨场景对象关系，生成带时间的事件表，再做连续骨架和细节。以我的输出要求和验收重点为准，不默认套用案例的 15 秒、60fps 或 128 BPM。每轮先修最影响观感与因果关系的差异，导出后用同时间轴左右对比验证。保留可编辑工程，列出实际采用的工具、参考来源、近似部分和未完成的检查。不要把复刻或多轮修改描述成原创或一次生成；涉及公开发布时先核对素材使用权。
